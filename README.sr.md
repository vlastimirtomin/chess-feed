# chess-feed

*English: see [README.md](README.md)*

RSS фид турнира са chess-results.com за унапред задату листу FIDE ID бројева. Овај репозиторијум садржи **код и радни
ток** и објављује фидове преко GitHub Pages-а. Листа играча, подешавања и памћење скрипте налазе се у посебном
**приватном** репозиторијуму.

## Шта ради

Скрипта претражује chess-results.com за сваки FIDE ID, преузима Excel табелу коју сајт нуди уз претрагу играча и
задржава турнире унутар временског прозора: завршене у последњих `finished_days` дана (подразумевано 33), оне у
току и предстојеће које се завршавају у наредних `upcoming_days` дана (подразумевано 366).

Када се играч први пут појави на неком турниру, у RSS фид се додаје ставка, на пример
*„Играч Б је пријављен за: Турнир X“* (глагол зависи од `M`/`F`). Турнир откривен тек пошто је завршен гласи
*„… је учествовао/учествовала на: …“*. Ако играч нестане са стартне листе турнира који још није завршен и остане
одсутан на `withdraw_after_days` различитих дана, додаје се једна ставка *„… више није на стартној листи: …“*.
Ништа се не најављује два пута. Текст је на српском ћирилицом, а линкови воде на српску (`lan=14`) страницу.

## Активни и неактивни играчи

У фајлу `players.txt` (приватни репозиторијум) сваки ред је `FIDE_ID  [A или I]  [M или F]  ознака`. Два слова могу
доћи било којим редоследом; подразумева се `A` (активан) и `M`.

- **Активни** играчи се проверавају унутар активног прозора (подразумевано 05:00 до 01:00, средњоевропско време),
  на најмање 4 сата размака: пет провера дневно.
- **Неактивни** играчи се проверавају једном дневно унутар ноћног прозора (подразумевано 01:00 до 05:00).
- Нови играчи се проверавају при првом покретању, у ма које време.

Радни ток креће у шест фиксних UTC времена дневно (`cron:` у `watch.yml`); скрипта одлучује ко је на реду, па је
већина покретања кратка. Сви бројеви су у `config.ini` у одељку `[schedule]`. Зимско/летње време решава скрипта.

## Како је постављено

| Репозиторијум | Видљивост | Садржи |
|---|---|---|
| овај (`chess-feed`) | јавни | `chess_watch.py`, `watch.yml`, README фајлове; фидови се одавде објављују преко Pages-а |
| `chess-watch` | **приватни** | `config.ini`, `players.txt`, `state/` (шта је најављено и дневник захтева за последњих 48 сати) |

Свако покретање преузима приватни репозиторијум поред кода, покреће скрипту, објављује фидове и враћа стање у
приватни репозиторијум. Стандардни GitHub покретачи су бесплатни за јавне репозиторијуме, па број покретања није
ограничен месечном квотом.

Адресе фидова (`[feed] name` у `config.ini`, подразумевано `rss`):

- сви играчи: `https://ВАШЕИМЕ.github.io/chess-feed/rss.xml`
- један играч: `https://ВАШЕИМЕ.github.io/chess-feed/rss-FIDEID.xml`

## Приватност и претраживачи

- Листа играча, подешавања и стање налазе се у приватном репозиторијуму. Јавни репозиторијум не садржи податке о
  играчима, а фидови се у њега не уписују (шаљу се директно на Pages).
- Дневници покретања овог јавног репозиторијума приказују само редне бројеве играча (`player #3`), никада ID или имена.
  Детаљан дневник, са ID бројевима и ознакама (сваки захтев и по један ред са резултатом за сваког играча), записује
  се у приватни репозиторијум у `state/request_log.txt` и чува последњих 48 сати.
- Фидови ипак садрже FIDE ID бројеве и ознаке, намерно. Ништа не води до њих, али свако ко зна или погоди адресу
  може да их чита, а XML фајл не може да носи `noindex` ознаку, па их претраживач ипак може преузети. Ако се то
  деси, код претраживача се може поднети захтев за уклањање.

## Обазривост према chess-results.com

- Једно учитавање обрасца за претрагу по покретању, затим по један захтев за сваког играча који је на реду, са
  паузом `delay_seconds` плус насумичних `jitter_seconds`. `max_players_per_run` ограничава једно покретање.
- Одговор `403` или `429` одмах прекида цело покретање; прекида га и три неуспеха заредом.
- Неуспела провера се никада не рачуна као „играч је напустио турнир“.
- Са `use_date_filter = yes` од сајта се траже само турнири који се завршавају унутар прозора. Скрипта то проверава
  у току рада и сама искључује филтер ако га сајт одбије. Режим `check-filter` пореди оба начина за тројицу играча.

## Складиште

Приватни репозиторијум мења само мале фајлове у `state/`. Овај репозиторијум се скоро никад не мења (ситан
комит „одржавања“ отприлике једном месечно да GitHub не би искључио распоред после 60 дана без активности).

## WebSub

Фидови оглашавају хабове наведене у `config.ini`, а радни ток их „пингује“ после објаве. Читач који подржава WebSub
за туђе фидове тада може одмах да буде обавештен; остали једноставно проверавају. Хаб који не ради само додаје ред са
ознаком FAIL у дневник захтева.

## Ограничења

- Могу се пронаћи само турнири са објављеном стартном листом.
- Скрипта чита незваничан Excel извоз; ако chess-results то промени, читање може да престане да ради.
- RSS ставка се не може повући из читача након што је испоручена.
- Заказана GitHub покретања могу да касне неколико минута.

## Брзо подешавање

1. Јавни репозиторијум `chess-feed`: отпремите `chess_watch.py`, `requirements.txt`, `.gitignore`, README фајлове и
   `.github/workflows/watch.yml`. *Settings → Pages → Source: GitHub Actions.*
2. Приватни репозиторијум `chess-watch`: оставите само `config.ini`, `players.txt` и `state/`. Обришите стари радни ток.
3. Направите fine-grained токен са дозволом *Contents: Read and write* само за приватни репозиторијум. У јавном
   репозиторијуму додајте Actions тајне `DATA_REPO_TOKEN` (токен) и `DATA_REPO` (`вашеиме/chess-watch`).
4. *Actions → Update tournaments → Run workflow:* `discover`, по жељи `check-filter`, па `update`.
5. Претплатите читач на `https://ВАШЕИМЕ.github.io/chess-feed/rss.xml`.
